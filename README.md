# Лабораторная работа №4

Дисциплина: Операционные системы и архитектура компьютера.
Вариант: 12. Язык: C11 и системные средства POSIX.
Среда разработки и проверок: Debian в WSL 2.

## Задание

Родитель принимает строки произвольной длины. Первый дочерний процесс
переводит текст в верхний регистр. Второй сокращает последовательности
обычных пробелов до одного. Родитель выводит результат.

Родитель и дети представлены отдельными программами. Данные передаются
через файл, отображённый в память с MAP_SHARED. Согласование выполняется
сигналами SIGUSR1 и SIGUSR2.

## Инструменты и сборка

В Debian:

```bash
sudo apt update
sudo apt install build-essential strace
```

Для сценариев проверок нужны Bash, awk, cmp, diff, grep, timeout,
mktemp и стандартные файловые утилиты. Для обработки текста нужна
доступная локаль C.UTF-8.

Все команды выполняются из корня проекта:

```bash
make
```

Создаются build/parent, build/child1 и build/child2.

```bash
make clean
```

Удаляет результаты сборки.

## Запуск

```bash
./build/parent
```

Вводите строки, завершая их клавишей Enter. Для окончания ввода нажмите
Ctrl+D в начале новой пустой строки. Для прерывания используйте Ctrl+C.

Пример: `привет   мир` преобразуется в `ПРИВЕТ МИР`.

Обработка файла:

```bash
./build/parent < input.txt > result.txt 2> diagnostics.log
```

Обработанный текст направляется в stdout. Диагностика с PID — в stderr.

## Архитектура и протокол

Родитель создаёт временный файл через mkstemp, устанавливает размер
через ftruncate и отображает файл через mmap. Затем через fork и execl
запускает двух детей, передавая путь к файлу. Каждый ребёнок открывает
его и создаёт собственное отображение.

Дети создаются один раз и обрабатывают сообщения в цикле.
Для каждой части текста:

1. Родитель записывает данные в общую область.
2. Родитель отправляет SIGUSR1 первому ребёнку.
3. Первый ребёнок меняет регистр и отвечает SIGUSR2.
4. Родитель отправляет SIGUSR1 второму ребёнку.
5. Второй ребёнок сокращает пробелы и отвечает SIGUSR2.
6. Родитель выводит результат.

Отправитель подтверждения проверяется по PID. До получения подтверждений
следующая часть не записывается. Рабочие сигналы блокируются до fork;
маска сохраняется после exec, что позволяет принять раннее уведомление.

После конца ввода передаётся MESSAGE_END. Дети подтверждают сообщение
и завершаются. Родитель получает их статусы через waitpid.

## Обработка текста

Общий блок содержит длину, вид сообщения и массив на 4096 байт.
Родитель динамически выделяет память для целой строки и передаёт её
частями. Фиксированного ограничения длины строки нет; фактический
предел определяется доступной памятью и представимостью размера.

Части формируются по границам символов UTF-8. Для изменения регистра
используются mbrtowc, towupper и wcrtomb в локали C.UTF-8.
Размер входной части оставляет запас для результата преобразования.
Это посимвольное преобразование регистра стандартной библиотеки.

Сокращаются только последовательности обычных пробелов U+0020.
Одиночные пробелы по краям сохраняются, табуляция не изменяется.
Состояние предыдущего пробела сохраняется между частями.
Пустые строки и отсутствие последнего перевода строки сохраняются.
Некорректный UTF-8 считается ошибкой.

## Завершение и ошибки

Родитель ожидает детей, снимает отображение, закрывает дескриптор
и удаляет имя временного файла. SIGINT и SIGTERM обрабатываются
как запрос остановки с последующей очисткой.

Ожидание подтверждения ограничено 30 секундами. Отказ ребёнка
обнаруживается при попытке обмена по отсутствию подтверждения либо
по ошибке отправки сигнала. Немедленное обнаружение отказа во время
ожидания пользовательского ввода не реализовано.

Коды завершения родителя: 0 — успех, 1 — ошибка,
130 — остановка по SIGINT, 143 — остановка по SIGTERM.

## Структура проекта

- src/parent.c — управление процессами, обменом и ресурсами;
- src/child1.c, src/child2.c — дочерние программы;
- src/shared.c, include/shared.h — отображение и формат общей области;
- src/sync.c, include/sync.h — согласование сигналами;
- src/text.c, include/text.h — преобразования текста;
- src/input.c, include/input.h — прерываемое чтение строк;
- tests/check_basic.sh — функциональные проверки;
- tests/check_launch_failure.sh — проверка отсутствующего child2;
- Makefile — автоматическая сборка.

## Проверки

```bash
bash tests/check_basic.sh
bash tests/check_launch_failure.sh
```

Первый сценарий проверяет 10 случаев: несколько строк, кириллицу,
пустой ввод, последнюю строку без перевода строки, пробелы по краям,
табуляцию, длинные строки, границы частей и некорректный UTF-8.
Также контролируется удаление временного файла.

Второй сценарий запускает копии программ во временной папке без child2.
Рабочая сборка не изменяется. Проверяются ошибка exec с кодом ребёнка 127,
код родителя 1 и удаление общего файла. Проверка занимает около 30 секунд.
Код 0 у самого сценария означает, что ожидаемая ошибка обработана правильно.

Оба сценария успешно выполнены. Вручную также проверены Ctrl+C при
ожидании ввода и SIGKILL первому ребёнку с последующей подачей строки.
В этих проверках подтверждено отсутствие оставшихся процессов и файла.

## Трассировка

```bash
printf 'hello   мир\n' | strace -f -o tests/run.strace ./build/parent
grep -E 'clone|execve|MAP_SHARED|kill|rt_sigtimedwait|wait4|unlink' tests/run.strace
```

-f включает наблюдение за детьми. Библиотечный fork может отображаться
как clone, execl — как execve, waitpid — как wait4, ожидание сигналов —
как rt_sigtimedwait. Полученная трассировка подтверждает создание детей,
общие отображения, обмен сигналами, успешные статусы и unlink.
